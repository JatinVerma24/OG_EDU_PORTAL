Operating Systems Core Concepts for Engineering Exams: Processes, Threads & Concurrency

The Operating System (OS) serves as the software bridge between physical hardware and user applications. This guide condenses the core exam concepts tested across all Indian university technical curricula.

1. Processes, Threads & PCB

A process is a program in execution containing four memory segments: Text (compiled code), Data (global variables), Heap (dynamic memory), and Stack (local variables, function calls). The Process Control Block (PCB) stores the process state, program counter, CPU registers, and open file descriptors.

A thread is a lightweight unit of CPU utilization within a process. Multiple threads share the process's code, data, and OS resources, but retain independent program counters, registers, and stacks.

2. CPU Scheduling Algorithms

Key scheduling policies evaluated on university exams include:

  • FCFS (First-Come, First-Served): Non-preemptive, suffers from the Convoy Effect (short jobs waiting behind long jobs).
  • SJF / SRTF (Shortest Job / Remaining Time First): Provably optimal for minimizing average waiting time, but vulnerable to starvation of longer processes.
  • Round Robin (RR): Preemptive scheduling using fixed time slices (quanta). Balances responsiveness for interactive multi-tasking systems.

3. Critical Section & Synchronization

When concurrent threads access shared variables, race conditions occur. Any valid solution to the Critical Section problem must satisfy three criteria:

  1. Mutual Exclusion: If process $P_i$ is executing in its critical section, no other processes can be executing in their critical sections.
  2. Progress: Only processes not in their remainder section can participate in deciding who enters next.
  3. Bounded Waiting: A bound must exist on the number of times other processes are allowed to enter after a process has requested entry.

4. Deadlocks & Banker's Algorithm

A deadlock requires four simultaneous Coffman conditions: Mutual Exclusion, Hold and Wait, No Preemption, and Circular Wait. The Banker's Algorithm performs resource allocation safety checks by calculating whether a safe execution sequence exists where: $\text{Need} = \text{Max} - \text{Allocation} \le \text{Available}$.

5. Virtual Memory & Paging

Virtual memory maps logical addresses to physical memory frames using a Page Table. The Translation Lookaside Buffer (TLB) caches frequent address translations to avoid dual memory accesses. When a referenced page is absent from physical RAM, a Page Fault triggers OS disk swapping using algorithms like FIFO, LRU, or Optimal Page Replacement.

6. Frequently Asked Questions

What causes thrashing in operating systems?

Thrashing occurs when the total memory demand of active processes exceeds physical RAM capacity. The CPU spends more time servicing page faults and swapping pages between disk and memory than executing actual instructions, collapsing system throughput.
